EVPN Multihoming: подключение к нескольким PE без ручного MC-LAG

Когда CE подключён к двум PE одновременно, кто-то должен решить, кто активно форвардит трафик и как не задублировать BUM. EVPN решает это через BGP, а не через проприетарный MC-LAG.

ИСТОЧНИКlinkmeup / СДСМ, гл. 12.2
ФОРМАТтеория + схема + квиз
ВРЕМЯ~9 минут
Один CE, два PE, один Ethernet Segment
ключевой узел на схемесоседний / промежуточный узел
  1. 1CE подключён физически к PE1 и PE2 одновременно
  2. 2Оба PE анонсируют один и тот же ESI через Route Type 4
  3. 3PE выбирают Designated Forwarder для BUM-трафика
  4. 4Unicast балансируется через Aliasing, BUM идёт только через DF

Со стороны CE это выглядит как обычный LACP-канал — он не знает и не должен знать, что на другом конце два разных PE.

01 — ТЕОРИЯ
Из чего состоит решение Multihoming

Шесть понятий — от проблемы дублирования до сравнения с MC-LAG.

Проще говоря: если клиентский коммутатор подключён сразу к двум PE, EVPN-MH решает, кто из них сейчас главный, чтобы трафик не задваивался.

Проблема multihoming
Если CE физически подключён к двум PE, оба могут получить один и тот же BUM-кадр и разослать его дважды — нужен механизм, кто из PE «главный».
Route Type 1 per-ESI
Анонс, которым PE сообщает остальным о своём участии в конкретном Ethernet Segment — на основе этих анонсов строится список PE на сегменте.
DF election
Алгоритм выбора Designated Forwarder среди всех PE, подключённых к одному ESI, чтобы BUM-трафик пересылался только с одного из них.
Route Type 1 per-EVI
Более гранулярный анонс на уровне конкретного EVPN-сервиса, используется для быстрого MAC Mass Withdrawal именно в рамках этого сервиса.
Aliasing
Механизм, позволяющий распределять unicast-трафик к multihomed MAC между несколькими PE, даже если MAC был выучен только на одном из них.
EVPN vs MC-LAG
MC-LAG — проприетарное решение конкретного вендора для active/active или active/standby пары; EVPN Multihoming делает то же самое стандартизированно через BGP.
— ЧАСТЫЕ ЗАБЛУЖДЕНИЯ
Что обычно путают

Типичные неверные представления про эту тему — и как на самом деле.

КажетсяЕсли устройство подключено к двум PE, трафик просто балансируется между ними без правил.
На делеНужен явный механизм DF (Designated Forwarder) election, который решает, какой PE сейчас пересылает BUM-трафик — иначе возникнут дубли и петли.
КажетсяMultihoming в EVPN работает только в режиме active/standby.
На делеEVPN поддерживает active/active multihoming — оба PE могут одновременно пересылать unicast-трафик к общему устройству.
02 — ПРОЦЕСС
Как CE получает резервирование через два PE

Четыре шага — от физического подключения до балансировки unicast.

  • 1Подключение — CE физически подключается к двум (или более) PE через один Ethernet Segment.
  • 2Анонс ESI — PE анонсируют участие в этом ESI через Route Type 4 друг другу.
  • 3DF election — между PE на этом ESI избирается Designated Forwarder для BUM.
  • 4Aliasing — unicast-трафик балансируется между PE, минуя ограничение «только через DF».
— ПРИМЕР
CLI-пример

Готовый конфиг для копирования — синтаксис Cisco IOS, адаптируйте под свою схему адресации.

Ethernet Segment на дуал-хомед порте 
Router(config)# interface Port-channel1
Router(config-if)# ethernet segment
Router(config-if-es)# identifier type 0 11.11.11.11.11.11.11.11.11
Router(config-if-es)# exit
Router# show evpn ethernet-segment

identifier должен быть одинаковым на обоих PE, к которым подключено общее устройство — иначе DF election не сработает как единый сегмент.

03 — ГЛОССАРИЙ
Термины модуля

Короткий справочник — можно оставить открытым рядом с CLI.

Ethernet Segment
Логическая группа физических подключений одного CE к нескольким PE, идентифицируемая общим ESI.
All-Active / Single-Active
Режимы multihoming: в All-Active все PE сегмента пересылают unicast одновременно, в Single-Active — только один.
DF election algorithm
Детерминированный алгоритм, гарантирующий, что все PE сегмента выберут одного и того же DF независимо друг от друга.
Split-horizon в EVPN
Защита от того, чтобы PE не отправил BUM-трафик обратно на тот же multihomed-сегмент, откуда он пришёл.
MC-LAG
Multi-Chassis Link Aggregation — проприетарная альтернатива EVPN Multihoming для active/active пары устройств.
Fast Convergence
Цель EVPN Multihoming: при падении одного PE трафик быстро переключается на оставшийся без ожидания долгих таймеров.
LAG со стороны CE
На CE обычно настраивается обычный LACP-канал, «не знающий», что на другом конце два разных PE, а не один коммутатор.
Per-ESI / Per-EVI
Два уровня анонсов Route Type 1: общий по всему сегменту и отдельный по каждому сервису на этом сегменте.
