Multicast: один поток, много получателей

Вместо N копий одного и того же потока для N получателей, multicast отправляет один поток, а сеть сама размножает его только там, где есть подписчики.

  2. 2IGMP: хосты сообщают роутеру о подписке
  3. 3PIM строит дерево доставки только туда, где есть подписчики
  4. 4Получатели получают поток без лишних копий на промежуточных линках

Сегменты сети без подписчиков вообще не видят этот трафик — дерево доставки строится избирательно.

01 — ТЕОРИЯ
Из чего состоит доставка multicast

Шесть понятий — от IGMP до Rendezvous Point.

Проще говоря: вместо копии потока каждому зрителю отдельно сеть строит одно дерево доставки и размножает поток только там, где есть подписчики.

Зачем нужен multicast
Вместо отдельной копии потока на каждого получателя (как в unicast) сеть размножает один поток только там, где реально есть подписчики.
IGMP
Internet Group Management Protocol — протокол, которым хосты сообщают ближайшему роутеру о подписке (join) или отписке (leave) от группы.
PIM
Protocol Independent Multicast — протокол построения дерева доставки трафика между роутерами; не зависит от конкретного unicast-протокола маршрутизации.
PIM Dense Mode
Трафик изначально флудится везде, а роутеры без подписчиков явно «обрезают» (prune) ветки — подходит, когда подписчиков много почти везде.
PIM Sparse Mode
Трафик доставляется только туда, где явно запросили (join) через Rendezvous Point — подходит, когда подписчиков мало и они разбросаны.
RP (Rendezvous Point)
Центральная точка встречи источника и получателей в PIM Sparse Mode — к ней изначально идёт дерево, пока не произойдёт SPT switchover.
— ЧАСТЫЕ ЗАБЛУЖДЕНИЯ
Что обычно путают

Типичные неверные представления про эту тему — и как на самом деле.

КажетсяMulticast-трафик автоматически доходит до всех, кто в сети.
На делеТрафик доставляется только туда, где есть активные подписчики (через IGMP от хостов и PIM между роутерами) — без подписки поток туда не пойдёт.
КажетсяMulticast работает как broadcast, просто на отдельном адресе.
На делеMulticast строит дерево доставки и размножает пакет только в точках ветвления — это принципиально эффективнее broadcast-флуда.
02 — ПРОЦЕСС
Как поток доходит от источника до подписчика

Четыре шага — от анонса потока до обрезки лишних веток.

  • 1Источник — отправляет поток на групповой multicast-адрес.
  • 2Join — хосты, которым нужен поток, сообщают об этом через IGMP.
  • 3Дерево — PIM строит дерево доставки только к тем сегментам, где есть подписчики.
  • 4Prune — роутеры без подписчиков на ветке обрезают её, не тратя полосу впустую.
— ПРИМЕР
CLI-пример

Готовый конфиг для копирования — синтаксис Cisco IOS, адаптируйте под свою схему адресации.

PIM Sparse-Mode с явным RP 
Router(config)# ip multicast-routing
Router(config)# interface GigabitEthernet0/0
Router(config-if)# ip pim sparse-mode
Router(config)# ip pim rp-address 10.0.0.1
Router# show ip mroute

ip pim sparse-mode нужен на каждом интерфейсе, через который может пойти multicast-трафик, включая линк к RP.

03 — ГЛОССАРИЙ
Термины модуля

Короткий справочник — можно оставить открытым рядом с CLI.

Multicast-адрес
Диапазон 224.0.0.0–239.255.255.255, зарезервированный под групповую доставку.
IGMP Snooping
Механизм на L2-коммутаторе, слушающий IGMP и не флудящий multicast-трафик на порты без подписчиков.
Querier
Устройство, периодически спрашивающее «кто ещё подписан?», поддерживая актуальность списка подписчиков IGMP.
SPT
Shortest Path Tree — дерево кратчайших путей от источника напрямую к получателям, к которому PIM Sparse Mode переключается после первого прихода трафика через RP.
RPT
Rendezvous Point Tree — дерево, построенное через RP, используется до SPT switchover.
Prune / Graft
Операции «обрезать» ветку без подписчиков и «прирастить» её обратно при появлении нового подписчика.
SSM
Source-Specific Multicast — режим, при котором получатель сразу указывает конкретный источник группы, не требует RP.
BIDIR-PIM
Режим PIM, где дерево строится в обе стороны через RP одновременно — полезен при множестве источников в одной группе.
