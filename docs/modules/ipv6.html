IPv6: адресация нового поколения без NAT и broadcast

IPv6 — не «IPv4 с более длинными адресами», а другая модель: нет broadcast, соседи находятся через NDP вместо ARP, а адресного пространства хватает, чтобы не изобретать NAT для экономии адресов.

ВРЕМЯ~10 минут
Базовая IPv6-маршрутизация между тремя роутерами
ключевой узел на схемесоседний / промежуточный узел
  1. 1R1: ipv6 address 2001:db8:0:1::1/64 — глобальный unicast на интерфейсе
  2. 2R1 ↔ R2: NDP (Neighbor Discovery) вместо ARP находит link-layer адрес соседа
  3. 3R2: ipv6 route ::/0 в сторону R3 — маршрут по умолчанию
  4. 4R3: получает пакет — путь построен без единого NAT на пути

Каждый интерфейс с IPv6 получает не только глобальный адрес, но и автоматический link-local (fe80::/10) — именно он чаще всего используется как next-hop во внутренних маршрутах.

01 — ТЕОРИЯ
Из чего состоит адресация IPv6

Шесть понятий — от типов адресов до того, почему NAT здесь не обязателен.

Проще говоря: у IPv6 адресов настолько много, что каждому устройству можно дать честный глобальный адрес напрямую, а вместо ARP и broadcast используются NDP и multicast.

Типы адресов
IPv6 знает unicast (одному получателю), multicast (группе) и anycast (ближайшему из группы одинаковых адресов). Broadcast как класса не существует вообще.
Link-local (fe80::/10)
Автоматически назначается на каждый IPv6-интерфейс, работает только в пределах одного сегмента и не маршрutizируется — но именно он часто используется как next-hop для соседних маршрутизаторов.
NDP вместо ARP
Neighbor Discovery Protocol поверх ICMPv6 находит link-layer адрес соседа (Neighbor Solicitation/Advertisement) и объявления роутера (Router Advertisement) — делает то же, что ARP + часть DHCP в IPv4.
SLAAC
Stateless Address Autoconfiguration — хост может сам собрать себе глобальный адрес из префикса, полученного в Router Advertisement, без отдельного DHCPv6-сервера.
Сокращение записи
Ведущие нули в каждой группе можно опускать, а одну последовательность нулевых групп подряд — заменить на ::, но только один раз в адресе, иначе запись станет неоднозначной.
Dual-stack
IPv4 и IPv6 обычно работают параллельно на одном интерфейсе на переходный период — это не «либо-либо», а сосуществование, пока IPv6 не станет основным.

Что обычно путают

Типичные неверные представления про эту тему — и как на самом деле.

КажетсяIPv6 использует broadcast так же, как IPv4.
На делеВ IPv6 broadcast не существует вообще — вместо него используется multicast (например, all-nodes ff02::1).
КажетсяNAT так же обязателен в IPv6, как и в IPv4.
На делеИз-за огромного адресного пространства IPv6 задуман без необходимости NAT для экономии адресов — хотя NPTv6 существует для отдельных задач вроде смены провайдера.
02 — ПРОЦЕСС
Как включить и проверить IPv6-маршрутизацию

Похоже на IPv4, но с парой обязательных дополнительных шагов.

  • 1ipv6 unicast-routing — глобально включить маршрутизацию IPv6 (без этого роутер ведёт себя как хост, а не как router).
  • 2ipv6 address на интерфейсе — назначить глобальный unicast-адрес; link-local появится автоматически.
  • 3NDP находит соседей — Neighbor Solicitation/Advertisement строит таблицу соседей, аналог ARP-кэша.
  • 4Статический или динамический маршрут — ipv6 route или OSPFv3/IPv6 BGP для построения таблицы маршрутизации.
  • 5Проверка — show ipv6 interface brief и show ipv6 route подтверждают, что адреса и маршруты на месте.
— ПРИМЕР
CLI-пример

Готовый конфиг для копирования — синтаксис Cisco IOS, адаптируйте под свою схему адресации.

Базовая настройка IPv6 на интерфейсе и статический маршрут 
Router(config)# ipv6 unicast-routing
Router(config)# interface GigabitEthernet0/0
Router(config-if)# ipv6 address 2001:db8:0:1::1/64
Router(config-if)# ipv6 enable
Router(config-if)# exit
Router(config)# ipv6 route ::/0 2001:db8:0:1::2
Router# show ipv6 interface brief
Router# show ipv6 route

ipv6 enable на интерфейсе включает link-local и обработку NDP, даже если вы по какой-то причине не назначаете глобальный адрес на этом интерфейсе.

— ПРАКТИКА
Лабораторная работа

Попробуйте сами в Packet Tracer/GNS3 или на реальном стенде, прежде чем открывать решение.

Два офисных роутера R1 и R2 соединены линком и должны обмениваться IPv6-трафиком; R2 смотрит в интернет через провайдера.

  1. Включите ipv6 unicast-routing на обоих роутерах
  2. Назначьте R1 адрес 2001:db8:0:1::1/64, R2 — 2001:db8:0:1::2/64 на общем линке
  3. Проверьте, что R1 видит link-local сосед R2 через show ipv6 neighbors
  4. Настройте на R2 маршрут по умолчанию в сторону провайдера
  5. С R1 проверьте связность до внешнего адреса через ping ipv6
Показать решение
Решение 
R1(config)# ipv6 unicast-routing
R1(config)# interface GigabitEthernet0/0
R1(config-if)# ipv6 address 2001:db8:0:1::1/64
R1(config-if)# exit
R1(config)# ipv6 route ::/0 2001:db8:0:1::2
R1# show ipv6 neighbors
R1# ping ipv6 2001:4860:4860::8888

Как проверить: show ipv6 route на R1 должен показать маршрут по умолчанию через R2, а ping ipv6 — получить ответ.

03 — ГЛОССАРИЙ
Термины модуля

Короткий справочник — можно оставить открытым рядом с CLI.

EUI-64
Способ автоматически собрать интерфейсную часть IPv6-адреса из MAC-адреса интерфейса.
NDP
Neighbor Discovery Protocol — набор ICMPv6-сообщений для поиска соседей, роутеров и автонастройки, заменяет ARP из IPv4.
RA / RS
Router Advertisement / Router Solicitation — объявление роутером своего префикса и явный запрос хостом такого объявления.
SLAAC
Stateless Address Autoconfiguration — автоматическая сборка адреса хостом на основе полученного префикса, без DHCPv6.
ULA (fc00::/7)
Unique Local Address — аналог приватных адресов IPv4 (RFC1918), не маршрутизируется в интернете.
Anycast
Один и тот же адрес назначен нескольким устройствам — пакет доставляется ближайшему из них по метрике маршрутизации.
Solicited-node multicast
Специальная multicast-группа, формируемая из последних 24 бит адреса — используется вместо ARP-broadcast для поиска конкретного соседа.
