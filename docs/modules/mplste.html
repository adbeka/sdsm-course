MPLS Traffic Engineering: явное управление путём трафика

Обычная маршрутизация выбирает путь по метрике IGP, не глядя на загрузку линков. MPLS TE резервирует полосу и может явно проложить путь в обход перегруженного участка.

  2. 2Но этот путь перегружен — недостаточно свободной полосы
  3. 3RSVP-TE резервирует полосу по альтернативному явному пути
  4. 4Трафик идёт через TE-туннель, обходя узкое место

IGP сам по себе никогда бы не выбрал этот более длинный путь — решение принимается поверх него, явно.

01 — ТЕОРИЯ
Из чего состоит решение MPLS TE

Шесть понятий — от проблемы обычного IGP до Fast Reroute.

Проще говоря: обычный MPLS едет по кратчайшему пути от IGP; TE позволяет явно проложить другой маршрут и держать наготове резервный на случай обрыва.

Проблема обычной маршрутизации
IGP (OSPF/ISIS) выбирает путь только по метрике, не учитывая реальную загрузку линков — кратчайший путь может быть перегружен, а более длинный — простаивать.
Traffic Engineering
Явное управление тем, по какому физическому пути пойдёт трафик, вместо того чтобы полагаться только на решение IGP.
RSVP-TE
Протокол резервирования, который не только распределяет метки, но и резервирует полосу вдоль выбранного пути, отслеживая доступный ресурс на каждом линке.
Explicit path
Администратор (или система) может явно задать список узлов, через которые должен пройти TE-туннель, а не полагаться на автоматический расчёт.
CSPF
Constraint-Based Routing — расчёт пути с учётом ограничений (доступная полоса, административные группы), а не только метрики.
Направление трафика в туннель
Трафик можно направить в TE-туннель разными способами: статический маршрут на туннель, PBR, автомаршрутизация (autoroute) или через метрику самого туннеля.
— ЧАСТЫЕ ЗАБЛУЖДЕНИЯ
Что обычно путают

Типичные неверные представления про эту тему — и как на самом деле.

КажетсяMPLS TE нужен только для резервирования на случай обрыва.
На делеTE прежде всего — инструмент инженерии трафика: явный контроль пути для балансировки нагрузки и SLA, резервирование (FRR) — лишь одна из возможностей.
КажетсяTE-туннель всегда идёт по кратчайшему IGP-пути.
На делеTE-путь считается с учётом ограничений (bandwidth, affinity/цвета линков) и может сознательно обходить кратчайший путь IGP, если тот перегружен.
02 — ПРОЦЕСС
Как трафик оказывается в TE-туннеле

Четыре шага — от того, что выбрал бы IGP, до реального пути через TE.

  • 1IGP-выбор — IGP посчитал бы кратчайший путь по метрике, не глядя на загрузку.
  • 2Обнаружение проблемы — этот путь перегружен или не подходит по ограничениям.
  • 3Резервирование — RSVP-TE резервирует полосу вдоль альтернативного пути.
  • 4Направление — трафик направляется в TE-туннель одним из способов.
— ПРИМЕР
CLI-пример

Готовый конфиг для копирования — синтаксис Cisco IOS, адаптируйте под свою схему адресации.

TE-туннель с явным путём 
Router(config)# interface Tunnel1
Router(config-if)# tunnel mode mpls traffic-eng
Router(config-if)# tunnel destination 10.0.0.5
Router(config-if)# tunnel mpls traffic-eng bandwidth 50000
Router(config-if)# tunnel mpls traffic-eng path-option 1 explicit name PRIMARY
Router# show mpls traffic-eng tunnels

bandwidth резервирует полосу вдоль всего пути — RSVP-TE откажет в установлении туннеля, если по дороге её не хватает.

03 — ГЛОССАРИЙ
Термины модуля

Короткий справочник — можно оставить открытым рядом с CLI.

LSP TE
Label Switched Path, построенный не обычным LDP, а через RSVP-TE с резервированием ресурсов.
Bandwidth reservation
Заявленный и зарезервированный объём полосы на каждом линке пути TE-туннеля.
Administrative group
Метки («цвета») на линках, позволяющие исключать или включать определённые линки в расчёт TE-пути.
CSPF
Constrained Shortest Path First — расчёт кратчайшего пути с учётом ограничений, а не только метрики.
Autoroute
Механизм, при котором TE-туннель автоматически учитывается в таблице маршрутизации как более предпочтительный путь.
Make-before-break
Техника пересчёта TE-туннеля: новый путь устанавливается до разрыва старого, чтобы избежать потери трафика.
FRR
Fast Reroute — заранее подготовленный обходной путь на случай обрыва линка, переключение за миллисекунды.
Head-end / Tail-end
Начальный и конечный узел TE-туннеля.
