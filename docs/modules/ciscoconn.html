Подключение к оборудованию: консоль и удалённый доступ

Прежде чем настраивать что-либо, нужно попасть в устройство — консоль, Telnet, SSH — и понимать разницу между режимами CLI, чтобы не потерять доступ на проде.

ВРЕМЯ~7 минут
Уровни доступа CLI
ключевой узел на схемесоседний / промежуточный узел
  1. 1User EXEC (>) — просмотр базовой информации, ничего не сломать
  2. 2Privileged EXEC (#) — полный просмотр состояния, show run, reload
  3. 3Global Config (config)# — правки, влияющие на всё устройство
  4. 4Interface Config (config-if)# — правки конкретного порта

Каждый следующий уровень — вложенный: из Interface Config можно выйти обратно в Global, но не наоборот минуя его.

01 — ТЕОРИЯ
Из чего состоит доступ к устройству

Пять понятий — от способов подключения до восстановления пароля.

Проще говоря: прежде чем что-то настраивать, нужно попасть в командную строку устройства — вживую через консоль или удалённо по SSH/Telnet.

Способы подключения
Консольный порт (всегда работает, даже без сети), Telnet (нешифрованный, устарел), SSH (шифрованный, стандарт де-факто) — у каждого свой сценарий использования.
User EXEC vs Privileged EXEC
User EXEC (>) даёт только просмотр; Privileged EXEC (#) открывает полный доступ, включая reload и запись конфигурации.
Global Configuration Mode
Режим, в котором правки применяются ко всему устройству целиком (hostname, VLAN, глобальные ACL и т.д.).
Interface Configuration Mode
Вложенный режим для настройки конкретного порта — не влияет на остальные интерфейсы.
Сброс пароля
Процедура восстановления доступа при потере пароля обычно требует физического доступа к консоли и перезагрузки в специальном режиме — сетевой доступ для этого не подходит.
— ЧАСТЫЕ ЗАБЛУЖДЕНИЯ
Что обычно путают

Типичные неверные представления про эту тему — и как на самом деле.

КажетсяTelnet и SSH — это одно и то же, просто разные порты.
На делеTelnet передаёт весь трафик, включая пароли, открытым текстом; SSH шифрует сессию — в проде Telnet использовать не стоит.
КажетсяКонсольный порт нужен только при первой настройке.
На делеКонсоль — единственный доступ к устройству, если сетевой интерфейс сконфигурирован неправильно или сеть недоступна (out-of-band управление).
02 — ПРОЦЕСС
От подключения до правки интерфейса

Четыре шага — каждый следующий требует пройти предыдущий.

  • 1Console/Telnet/SSH — подключение к устройству одним из трёх способов.
  • 2User EXEC (>) — базовый уровень доступа сразу после входа.
  • 3Privileged EXEC (#) — вход по enable-паролю открывает полный доступ.
  • 4Config mode — правки конфигурации, от глобальных до уровня конкретного интерфейса.
— ПРИМЕР
CLI-пример

Готовый конфиг для копирования — синтаксис Cisco IOS, адаптируйте под свою схему адресации.

Базовая настройка доступа к устройству 
Switch> enable
Switch# configure terminal
Switch(config)# hostname SW1
SW1(config)# enable secret Cisco123
SW1(config)# username admin secret StrongPass1
SW1(config)# ip domain-name lab.local
SW1(config)# crypto key generate rsa modulus 2048
SW1(config)# line vty 0 4
SW1(config-line)# transport input ssh
SW1(config-line)# login local
SW1(config-line)# exit
SW1(config)# end
SW1# write memory

crypto key generate rsa обязателен для SSH — без ключей transport input ssh не заработает.

03 — ГЛОССАРИЙ
Термины модуля

Короткий справочник — можно оставить открытым рядом с CLI.

Console port
Физический последовательный порт для локального управления устройством, работает даже без сети.
Telnet
Нешифрованный протокол удалённого управления, считается устаревшим для продакшена.
SSH
Шифрованный протокол удалённого управления, стандарт де-факто.
Enable password / secret
Пароль для перехода из User EXEC в Privileged EXEC.
running-config / startup-config
Активная конфигурация в памяти устройства и сохранённая конфигурация, которая загрузится при перезагрузке.
ROMMON
Режим восстановления на низком уровне, используется при сбросе пароля или восстановлении образа ОС.
