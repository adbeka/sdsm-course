EVPN: BGP вместо флуда для изучения MAC

VPLS учит MAC-адреса флудом неизвестного трафика в data plane. EVPN переносит эту задачу в control plane через BGP — MAC-адреса анонсируются как обычные маршруты, а не выясняются флудом.

ИСТОЧНИКlinkmeup / СДСМ, гл. 12.1
ФОРМАТтеория + схема + квиз
ВРЕМЯ~11 минут
MAC-адрес анонсируется до прихода трафика
ключевой узел на схемесоседний / промежуточный узел
  1. 1CE1 отправляет кадр, PE1 узнаёт его MAC локально
  2. 2PE1 анонсирует MAC через BGP (Route Type 2), не ждёт флуда
  3. 3PE2 получает MAC-анонс заранее, до прихода первого кадра
  4. 4Трафик к этому MAC идёт сразу по известному пути, без learning-флуда

В VPLS этот же результат достигался бы флудом неизвестного unicast — здесь PE узнаёт о MAC заранее, через маршрутную рекламу.

01 — ТЕОРИЯ
Из чего состоит решение EVPN

Шесть понятий — от проблемы VPLS до EVPN как замены L3VPN.

Проще говоря: EVPN анонсирует MAC- и IP-адреса через BGP как обычные маршруты — это быстрее и надёжнее, чем старое обучение адресов флудом.

Проблема VPLS
VPLS учит MAC-адреса классическим data-plane флудом неизвестного трафика — при росте сети это создаёт лишнюю нагрузку и медленную сходимость.
EVPN control plane
MAC-адреса (и опционально IP) анонсируются через MP-BGP как обычные маршруты — соседние PE узнают о них заранее, а не выясняют флудом.
Route Type 2
MAC/IP Advertisement Route — основной тип маршрута EVPN, которым PE анонсирует конкретный MAC (и его IP) остальным PE.
Route Type 3
Inclusive Multicast Route — используется для доставки BUM-трафика (broadcast/unknown-unicast/multicast) через дерево или ingress replication.
ESI и Route Type 1
Ethernet Segment Identifier идентифицирует сегмент, к которому CE подключён через несколько PE; Route Type 1 сигнализирует об этом остальным.
EVPN как L3VPN
EVPN умеет переносить не только MAC, но и IP-маршруты (IRB) — фактически объединяя L2VPN и L3VPN в одной технологии.
— ЧАСТЫЕ ЗАБЛУЖДЕНИЯ
Что обычно путают

Типичные неверные представления про эту тему — и как на самом деле.

КажетсяEVPN — это просто новая версия VPLS с другим названием.
На делеEVPN использует BGP control-plane для анонса MAC/IP адресов вместо data-plane обучения флудом — это устраняет unknown-unicast флудинг и ускоряет конвергенцию.
КажетсяВ EVPN, как и в VPLS, MAC-адреса узнаются только через флуд.
На делеВ EVPN MAC (и IP) анонсируются через MP-BGP как обычные маршруты — узнавание активное, а не пассивное.
02 — ПРОЦЕСС
Как PE узнаёт чужой MAC заранее

Четыре шага — от локального обучения до готового пути на удалённом PE.

  • 1Локальное обучение — PE1 узнаёт MAC-адрес хоста за CE1 обычным способом.
  • 2BGP-анонс — PE1 анонсирует этот MAC через Route Type 2 остальным PE.
  • 3Заблаговременное получение — PE2 заносит MAC в таблицу до прихода трафика.
  • 4Без флуда — трафик к этому MAC сразу идёт по известному пути.
— ПРИМЕР
CLI-пример

Готовый конфиг для копирования — синтаксис Cisco IOS, адаптируйте под свою схему адресации.

EVPN control-plane поверх MP-BGP 
Router(config)# l2vpn evpn
Router(config-evpn)# router-id 10.0.0.1
Router(config)# router bgp 65500
Router(config-router)# address-family l2vpn evpn
Router(config-router-af)# neighbor 10.0.0.2 activate
Router# show bgp l2vpn evpn summary

Без активации l2vpn evpn address-family соседи будут обмениваться обычными IPv4-маршрутами, а не MAC/IP-анонсами EVPN.

03 — ГЛОССАРИЙ
Термины модуля

Короткий справочник — можно оставить открытым рядом с CLI.

EVI
EVPN Instance — аналог VPN-instance в VPLS, идентифицирует конкретный L2VPN-сервис в EVPN.
ESI
Ethernet Segment Identifier — идентификатор сегмента при multihomed-подключении CE к нескольким PE.
BUM-трафик
Broadcast, Unknown-unicast, Multicast — трафик, требующий доставки на все PE сервиса, а не по конкретному MAC.
DF
Designated Forwarder — PE, выбранный ответственным за пересылку BUM-трафика на multihomed-сегмент, чтобы не было дублей.
Aliasing
Механизм, позволяющий распределять трафик к multihomed MAC между несколькими PE, а не слать его только через один.
MAC Mass Withdrawal
Быстрый отзыв сразу всех MAC-адресов, анонсированных через упавший ESI, вместо ожидания таймаута по каждому отдельно.
IRB
Integrated Routing and Bridging — механизм, позволяющий маршрутизировать между bridge-доменами прямо на PE в рамках EVPN.
Route Type 4
Ethernet Segment Route — используется для автоматического обнаружения других PE на том же multihomed-сегменте и выбора DF.
