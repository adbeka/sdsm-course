Планирование сети: проектирование до развёртывания

Прежде чем тянуть кабель, сеть проектируют на бумаге — документация, схемы, IP-план и VLAN-план экономят часы на инциденте, который случится через полгода.

01 — ТЕОРИЯ
Из чего состоит план сети

Пять понятий — база, на которую опирается весь остальной курс.

Проще говоря: сначала считают, сколько нужно адресов, VLAN и уровней сети — и только потом идут покупать оборудование и тянуть кабель.

Документация сети
Единый источник правды о сети: что где стоит, зачем, кто отвечает — экономит часы на инциденте, который случится через полгода.
Схемы сети
Обычно нужно минимум три уровня: физическая (L1, кабели/порты), канальная (L2, VLAN/trunk) и логическая (L3, IP/маршруты) — каждая отвечает на свой вопрос.
IP-план
Адресация закладывается с запасом на рост: явно выделенные диапазоны под серверы, пользователей, VPN, management — чтобы не переразбивать сеть через год.
Список VLAN
Заранее согласованная нумерация VLAN по назначению (данные/голос/management/DMZ) — избавляет от коллизий номеров между площадками.
План подключения по портам
Таблица «порт коммутатора — что подключено — VLAN — заметка», которая экономит время диагностики больше, чем любая другая часть документации.
— ЧАСТЫЕ ЗАБЛУЖДЕНИЯ
Что обычно путают

Типичные неверные представления про эту тему — и как на самом деле.

КажетсяПлан сети — формальность для галочки, можно донастроить по ходу дела.
На делеНезадокументированная адресация и VLAN-план быстро превращаются в хаос — ошибки IP-конфликтов и путаницы обходятся дороже часа планирования.
КажетсяДостаточно одной схемы «как есть сейчас».
На делеНужны минимум две: логическая (IP/VLAN/протоколы) и физическая (кабели, порты, стойки) — они решают разные задачи при диагностике.
02 — ПРОЦЕСС
В каком порядке обычно планируют

Четыре шага — от общего описания до конкретного порта.

  • 1Документация — фиксируется, что за сеть, для чего, кто отвечает.
  • 2Схема сети — рисуется L1/L2/L3 топология.
  • 3IP-план — адресация распределяется по сегментам с запасом.
  • 4План портов — каждое физическое подключение фиксируется заранее.
— ПРИМЕР
CLI-пример

Готовый конфиг для копирования — синтаксис Cisco IOS, адаптируйте под свою схему адресации.

Пример плана адресации (не CLI, а артефакт планирования) 
# VLAN-план
VLAN 10   USERS        10.10.10.0/24   gw 10.10.10.1
VLAN 20   SERVERS      10.10.20.0/24   gw 10.10.20.1
VLAN 999  NATIVE/UNUSED

# Адресация транзитных линков
SW1 <-> SW2   10.10.99.0/30
SW1 <-> RTR1  10.10.99.4/30

На этапе планирования CLI ещё нет — есть таблица адресации и VLAN-план, по которым потом пишутся реальные конфиги.

03 — ГЛОССАРИЙ
Термины модуля

Короткий справочник — можно оставить открытым рядом с CLI.

L1/L2/L3 схема
Три отдельных уровня документации сети: физический (кабели), канальный (VLAN/trunk), логический (IP/маршруты).
IP-план
Таблица распределения адресных диапазонов по сегментам сети с запасом на рост.
VLAN-план
Согласованная нумерация VLAN по всей сети, единая для всех площадок.
Single Source of Truth
Принцип, при котором документация сети хранится в одном согласованном месте, а не расползается по головам инженеров.
Change Management
Процесс фиксации изменений в сети, чтобы документация не расходилась с реальностью.
Capacity Planning
Закладка запаса (адресов, портов, полосы) при планировании, чтобы не переделывать сеть при первом же росте.
