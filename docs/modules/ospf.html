OSPF: сеть, которая сама строит карту

В отличие от статики, OSPF рассылает соседям состояние своих линков — и каждый роутер локально строит по этим данным полную карту сети и сам считает кратчайшие пути.

  2. 2Init — Hello получены, но себя в списке соседа мы пока не видим
  3. 32-Way — двусторонний Hello, соседство установлено, DR/BDR выбраны
  4. 4Full — базы LSDB синхронизированы, маршруты рассчитаны

Только после Full состояния роутеры считают друг друга полноценными OSPF-соседями для расчёта SPF.

01 — ТЕОРИЯ
Из чего состоит решение OSPF

Шесть понятий — от link-state подхода до того, зачем нужны области.

Проще говоря: вместо статических маршрутов роутеры сами обмениваются картой сети и пересчитывают путь, если что-то сломалось.

Link-State vs Distance Vector
OSPF (link-state) рассылает состояние своих линков всем в области, и каждый роутер сам строит полную карту. Distance Vector (как RIP) просто передаёт соседям итоговые метрики, не видя топологию целиком.
LSA / LSDB
LSA (Link-State Advertisement) — сообщение о состоянии линка. LSDB — база всех LSA, из которой SPF считает дерево кратчайших путей.
SPF (алгоритм Дейкстры)
По данным LSDB каждый роутер независимо считает кратчайшие пути до всех сетей — отсюда одинаковая картина маршрутов у всех роутеров области.
Area
Деление сети на области ограничивает размер LSDB и объём пересчётов SPF при изменениях. Area 0 (backbone) обязательна и связывает остальные области.
DR / BDR
На multi-access сегментах (Ethernet) выбираются Designated и Backup Designated Router, чтобы не строить full-mesh соседств между всеми роутерами сегмента.
Metric (cost)
В OSPF метрика — это cost, обратно пропорциональный полосе линка. Путь с наименьшей суммой cost выигрывает.

Что обычно путают

Типичные неверные представления про эту тему — и как на самом деле.

КажетсяOSPF выбирает маршрут по количеству хопов, как RIP.
На делеOSPF считает суммарную метрику (cost) на основе пропускной способности линков — быстрый путь через много хопов может быть предпочтительнее короткого, но медленного.
КажетсяВсе роутеры в OSPF-сети должны быть в одной area.
На делеМногоareaый дизайн (с area 0 как backbone) — стандартная практика: ограничивает размер базы LSA и ускоряет сходимость в больших сетях.
02 — ПРОЦЕСС
Как два роутера становятся полноценными соседями

Строгая последовательность — соседство не может перескочить сразу в Full, минуя предыдущие шаги.

  • 1Down — сосед ещё не обнаружен, Hello-пакеты не получены.
  • 2Init — Hello получены, но собственный Router ID пока не виден в чужом Hello.
  • 32-Way — двусторонний обмен Hello подтверждён, на сегменте выбираются DR/BDR.
  • 4Full — базы LSDB полностью синхронизированы, соседство готово для расчёта маршрутов.
— ПРИМЕР
CLI-пример

Готовый конфиг для копирования — синтаксис Cisco IOS, адаптируйте под свою схему адресации.

Базовый OSPF с двумя area 
Router(config)# router ospf 1
Router(config-router)# router-id 1.1.1.1
Router(config-router)# network 10.0.0.0 0.0.0.255 area 0
Router(config-router)# network 10.0.1.0 0.0.0.255 area 1
Router(config-router)# passive-interface GigabitEthernet0/2
Router# show ip ospf neighbor

passive-interface на порту к хостам — OSPF не шлёт туда Hello, но подсеть всё равно анонсируется.

03 — ГЛОССАРИЙ
Термины модуля

Короткий справочник — можно оставить открытым рядом с CLI.

Hello-пакет
Служебное сообщение OSPF для обнаружения соседей и поддержания соседства (по умолчанию раз в 10 секунд на Ethernet).
Router ID
Уникальный идентификатор роутера в OSPF-домене, обычно самый большой loopback-адрес или задаётся вручную.
Area 0 (backbone)
Обязательная центральная область, через которую должны проходить маршруты между всеми остальными областями.
ABR
Area Border Router — роутер, стоящий на границе между двумя областями.
ASBR
Autonomous System Boundary Router — роутер, который заводит внешние маршруты (например, из BGP) в OSPF-домен.
Stub area
Область, в которую не пускают внешние LSA, чтобы уменьшить размер LSDB на периферии.
ECMP
Equal-Cost Multi-Path — балансировка трафика между несколькими путями с одинаковым cost.
Dead Interval
Время без Hello от соседа, после которого сосед считается недоступным (по умолчанию 4× Hello Interval).
