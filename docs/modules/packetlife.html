Packet Life: что внутри коробки происходит с пакетом

CLI показывает только команды и их результат. Реальная скорость обработки пакета определяется железом — какие чипы что делают и как устроена архитектура коммутирующего устройства.

ключевой узел на схемесоседний / промежуточный узел
  1. 1Пакет приходит на физический интерфейс (PIC)
  2. 2Forwarding Engine ищет решение в TCAM/CAM
  3. 3Пакет передаётся через фабрику коммутации на нужную линейную карту
  4. 4Пакет уходит с исходящего интерфейса после QoS-обработки

Всё это происходит в железе (ASIC/TCAM), без участия CPU — CPU подключается только для локальных пакетов и control plane.

01 — ТЕОРИЯ
Из чего состоит архитектура устройства

Шесть понятий — от плоскостей до транзитных и локальных пакетов.

Проще говоря: путь пакета внутри коммутатора — это конвейер: приём, разбор заголовка, поиск в таблице, буферизация и отправка на нужный порт.

Data / Control / Management Plane
Data plane пересылает трафик (быстро, в железе), Control plane считает маршруты и строит таблицы (медленнее, в софте), Management plane — то, чем управляет администратор.
TCAM
Ternary Content-Addressable Memory — специализированная память, позволяющая искать совпадение (включая wildcard-биты) за одну операцию — основа быстрой пересылки и ACL.
ASIC
Application Specific Integrated Circuit — чип, спроектированный под конкретную задачу; быстрее универсального CPU, но не перепрограммируется.
Линейная карта
Интерфейсный модуль устройства, содержащий физические порты, Forwarding Engine и, часто, локальный TCAM/буферы.
Фабрика коммутации
Внутренняя «шина» шасси, через которую пакет передаётся с одной линейной карты на другую внутри одного устройства.
Транзитные vs локальные пакеты
Транзитный пакет обрабатывается целиком в data plane (ASIC/TCAM); локальный пакет (например, BGP-обновление) поднимается до control plane на CPU.
— ЧАСТЫЕ ЗАБЛУЖДЕНИЯ
Что обычно путают

Типичные неверные представления про эту тему — и как на самом деле.

КажетсяКоммутатор пересылает пакет мгновенно, без задержек.
На делеПакет проходит через конвейер обработки (парсинг, lookup, буферизация) — при перегрузке буферов пакеты могут теряться или задерживаться.
КажетсяВсе порты коммутатора имеют одинаковый буфер — это не важно.
На делеРазмер и архитектура буферов (shared vs dedicated) сильно влияют на поведение при микро-всплесках трафика и на потери пакетов в периоды перегрузки.
02 — ПРОЦЕСС
Что происходит внутри устройства

Четыре шага — от приёма на физический порт до отправки.

  • 1Приём — пакет принимается на физический интерфейс линейной карты (PIC).
  • 2Поиск решения — Forwarding Engine ищет решение о пересылке в TCAM/CAM за одну операцию.
  • 3Фабрика — если исходящий интерфейс на другой линейной карте, пакет передаётся через фабрику коммутации.
  • 4Отправка — пакет проходит QoS-обработку и уходит с исходящего интерфейса.

03 — ГЛОССАРИЙ
Термины модуля

Короткий справочник — можно оставить открытым рядом с CLI.

CPU
Универсальный процессор, обрабатывающий control plane и локальные пакеты — медленнее ASIC для пересылки трафика.
RAM
Оперативная память для хранения таблиц и рабочих данных control plane.
CAM
Content-Addressable Memory — память для точного поиска (например, MAC-таблица).
FPGA
Field Programmable Gate Array — перепрограммируемый чип, гибче ASIC, но обычно медленнее и дороже в пересчёте на функцию.
NP
Network Processor — процессор, специализированный на обработке пакетов, но более гибкий и программируемый, чем чистый ASIC.
SerDes
Serializer/Deserializer — компонент, преобразующий параллельные данные внутри чипа в последовательный поток для передачи по линии.
Forwarding Engine
Часть линейной карты, принимающая решение о пересылке конкретного пакета на основе таблиц в TCAM.
Distributed Control Plane
Архитектура, при которой каждая линейная карта имеет собственный локальный процессор для части задач control plane.
