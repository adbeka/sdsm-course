AAA и 802.1X: аутентификация на порту до допуска в сеть

Порт коммутатора по умолчанию доверяет всему, что в него воткнули. 802.1X требует подтвердить личность устройства через RADIUS-сервер, прежде чем порт начнёт пропускать обычный трафик.

ФОРМАТтеория + схема + квиз
ВРЕМЯ~9 минут
Три роли 802.1X: supplicant, authenticator, authentication server
ключевой узел на схемесоседний / промежуточный узел
  1. 1PC1 → SW1: EAPOL-Start — устройство просит начать аутентификацию
  2. 2SW1 → PC1: EAP-Request Identity — порт пока в состоянии unauthorized
  3. 3SW1 → RADIUS: Access-Request с учётными данными клиента
  4. 4RADIUS → SW1: Access-Accept — порт переходит в authorized, трафик разрешён

До Access-Accept коммутатор пропускает только служебный EAPOL-трафик — обычные кадры клиента порт просто не форвардит, каким бы MAC он ни представился.

01 — ТЕОРИЯ
Из чего состоит 802.1X

Шесть понятий: от трёх ролей протокола до того, чем RADIUS отличается от TACACS+.

Проще говоря: пока устройство не подтвердит личность через RADIUS-сервер, порт коммутатора пропускает только служебные пакеты аутентификации — и ничего больше.

Supplicant
ПО на клиентском устройстве (обычно встроено в ОС), которое инициирует 802.1X-обмен и предъявляет учётные данные.
Authenticator
Коммутатор (или точка доступа) — посредник между supplicant и сервером аутентификации. Сам не проверяет пароли, только держит порт закрытым до ответа сервера.
Authentication server
Обычно RADIUS-сервер: хранит или проверяет учётные данные и решает, разрешить доступ или нет.
EAP / EAPOL
Extensible Authentication Protocol — гибкий формат обмена учётными данными (пароль, сертификат и т.д.), EAPOL — его версия поверх Ethernet между supplicant и authenticator.
RADIUS vs TACACS+
RADIUS шифрует только пароль и объединяет authentication/authorization в одном обмене. TACACS+ шифрует всю сессию и разделяет AAA на отдельные этапы — чаще используется для управления самими сетевыми устройствами.
MAB (MAC Authentication Bypass)
Резервный механизм для устройств без supplicant (принтеры, IP-камеры) — коммутатор аутентифицирует их просто по MAC-адресу через тот же RADIUS.
— ЧАСТЫЕ ЗАБЛУЖДЕНИЯ
Что обычно путают

Типичные неверные представления про эту тему — и как на самом деле.

Кажется802.1X и port security — одно и то же.
На делеPort security просто ограничивает набор MAC-адресов на порту без проверки личности; 802.1X — полноценная аутентификация через RADIUS с учётными данными.
КажетсяRADIUS и TACACS+ взаимозаменяемы без разницы.
На делеRADIUS шифрует только пароль и объединяет AAA в одном пакете; TACACS+ шифрует всю сессию и разделяет этапы — поэтому его чаще выбирают для управления самими сетевыми устройствами.
02 — ПРОЦЕСС
Как проходит 802.1X-аутентификация порта

Последовательность из трёх сторон — порт остаётся закрытым, пока не получен явный Access-Accept.

  • 1EAPOL-Start — supplicant инициирует обмен (или authenticator сам запрашивает Identity при линкапе).
  • 2EAP-Request/Response Identity — коммутатор запрашивает личность, клиент отвечает.
  • 3RADIUS Access-Request — authenticator пересылает данные на сервер аутентификации.
  • 4Access-Accept / Access-Reject — сервер решает, пускать устройство или нет.
  • 5Порт authorized — только теперь обычный трафик клиента начинает форвардиться.
— ПРИМЕР
CLI-пример

Готовый конфиг для копирования — синтаксис Cisco IOS, адаптируйте под свою схему адресации.

802.1X на порту доступа с RADIUS и MAB-резервом 
Router(config)# aaa new-model
Router(config)# radius server RAD1
Router(config-radius-server)# address ipv4 10.10.10.60 auth-port 1812 acct-port 1813
Router(config-radius-server)# key SharedSecret123
Router(config)# aaa authentication dot1x default group radius
Router(config)# dot1x system-auth-control
Router(config)# interface GigabitEthernet0/1
Router(config-if)# switchport mode access
Router(config-if)# authentication port-control auto
Router(config-if)# dot1x pae authenticator
Router(config-if)# mab

mab на порту — это резервный сценарий: если supplicant не ответил за отведённое время, коммутатор пробует аутентифицировать устройство по MAC через тот же RADIUS.

— ПРАКТИКА
Лабораторная работа

Попробуйте сами в Packet Tracer/GNS3 или на реальном стенде, прежде чем открывать решение.

На порту Gi0/1 подключается корпоративный ноутбук с supplicant, но иногда в тот же порт втыкают сетевой принтер без поддержки 802.1X.

  1. Настройте RADIUS-сервер 10.10.10.60 с общим ключом
  2. Включите dot1x system-auth-control глобально
  3. Настройте порт Gi0/1 в режим authentication port-control auto
  4. Добавьте MAB как резервный механизм для принтера
  5. Проверьте состояние порта через show authentication sessions
Показать решение
Решение 
Router(config)# radius server RAD1
Router(config-radius-server)# address ipv4 10.10.10.60 auth-port 1812 acct-port 1813
Router(config-radius-server)# key SharedSecret123
Router(config)# aaa new-model
Router(config)# aaa authentication dot1x default group radius
Router(config)# dot1x system-auth-control
Router(config)# interface GigabitEthernet0/1
Router(config-if)# authentication port-control auto
Router(config-if)# dot1x pae authenticator
Router(config-if)# mab
Router# show authentication sessions interface GigabitEthernet0/1

Как проверить: show authentication sessions должен показать метод (dot1x или mab) и статус Authz Success для подключённого устройства.

03 — ГЛОССАРИЙ
Термины модуля

Короткий справочник — можно оставить открытым рядом с CLI.

Supplicant
Программный клиент на конечном устройстве, инициирующий 802.1X-аутентификацию.
Authenticator
Сетевое устройство (коммутатор/точка доступа), которое держит порт закрытым до подтверждения от сервера.
RADIUS
Протокол AAA, шифрующий пароль и объединяющий authentication/authorization в одном обмене поверх UDP.
TACACS+
Протокол AAA от Cisco, шифрующий сессию целиком и разделяющий authentication/authorization/accounting на отдельные этапы поверх TCP.
EAP
Extensible Authentication Protocol — гибкий контейнер для разных методов аутентификации (пароль, сертификат, токен).
MAB
MAC Authentication Bypass — аутентификация устройства по MAC-адресу вместо полноценного 802.1X, для устройств без supplicant.
dot1x port-control
Режим порта: auto (ждать аутентификацию), force-authorized (всегда открыт) или force-unauthorized (всегда закрыт).
