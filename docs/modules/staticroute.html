Статическая маршрутизация: явно заданный маршрут

Статический маршрут — это явно прописанная администратором запись «куда идти дальше». Никакого протокола, никакого автоматического пересчёта — только то, что вы сами указали.

01 — ТЕОРИЯ
Из чего состоит решение о маршруте

Шесть понятий — от InterVLAN Routing до floating static route.

Проще говоря: статический маршрут — это когда администратор вручную говорит роутеру «пакеты в такую-то сеть отправляй туда-то», без всякого протокола.

InterVLAN Routing
Трафик между VLAN не может пройти без L3-устройства: либо роутер с несколькими интерфейсами (router-on-a-stick), либо L3-коммутатор с SVI.
Принципы маршрутизации
Роутер выбирает маршрут по принципу longest prefix match — самый длинный (самый точный) подходящий префикс в таблице побеждает.
Административная дистанция
Показатель доверия к источнику маршрута (статика, OSPF, BGP) — при конфликте источников побеждает маршрут с меньшей AD, а не более «правильный» сам по себе.
Статический маршрут
Явно прописанная администратором запись «для такой-то сети — вот такой next-hop». Не пересчитывается автоматически при изменениях в сети.
Маршрут по умолчанию
Специальный статический маршрут 0.0.0.0/0 — «если ничего более точного не нашлось, отправляй сюда».
Floating static route
Статический маршрут с искусственно завышенной административной дистанцией — используется как резервный, включается только если основной маршрут пропал.
— ЧАСТЫЕ ЗАБЛУЖДЕНИЯ
Что обычно путают

Типичные неверные представления про эту тему — и как на самом деле.

КажетсяСтатические маршруты — устаревший подход, везде используют динамику.
На делеСтатика по-прежнему используется для default route, маленьких сетей и явного контроля — простая, предсказуемая и не требует ресурсов на протокол.
КажетсяЕсли маршрут прописан статически — трафик обязательно пойдёт по нему.
На делеБолее специфичный префикс (длиннее маска) или маршрут с более низким AD победит в таблице маршрутизации, даже если статика тоже прописана.
02 — ПРОЦЕСС
Как роутер решает, куда отправить пакет

Четыре шага — от прихода пакета до отправки на next-hop.

  • 1Поиск — пакет приходит на роутер, ищется совпадение по таблице маршрутизации.
  • 2Longest match — среди всех совпадений выбирается запись с самым длинным префиксом.
  • 3AD tie-break — при конфликте источников на одну сеть побеждает запись с меньшей административной дистанцией.
  • 4Отправка — пакет уходит на next-hop, указанный в выбранной записи.
— ПРИМЕР
CLI-пример

Готовый конфиг для копирования — синтаксис Cisco IOS, адаптируйте под свою схему адресации.

Статические маршруты, включая резервный 
Router(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1
Router(config)# ip route 10.20.0.0 255.255.0.0 192.168.1.2
Router(config)# ip route 10.20.0.0 255.255.0.0 192.168.1.3 200
Router# show ip route static

Второй маршрут до 10.20.0.0/16 с AD 200 — это резервный (floating static), он включится только если основной пропадёт из таблицы.

03 — ГЛОССАРИЙ
Термины модуля

Короткий справочник — можно оставить открытым рядом с CLI.

Longest Prefix Match
Принцип выбора маршрута: чем длиннее (точнее) совпадающий префикс, тем выше приоритет записи.
Административная дистанция
Числовой показатель доверия к источнику маршрута; меньше — предпочтительнее.
Next-hop
IP-адрес следующего устройства, на который отправляется пакет для данного маршрута.
Default route
Маршрут 0.0.0.0/0, используемый, если для сети назначения нет более точной записи.
Floating static route
Резервный статический маршрут с завышенной AD, активируется только при пропадании основного маршрута.
Router-on-a-stick
Схема, при которой один физический интерфейс роутера через subinterfaces обслуживает маршрутизацию между несколькими VLAN.
SVI
Switch Virtual Interface — виртуальный L3-интерфейс VLAN на L3-коммутаторе, альтернатива router-on-a-stick.
Recursive lookup
Ситуация, когда next-hop статического маршрута сам требует дополнительного поиска в таблице, чтобы определить исходящий интерфейс.
