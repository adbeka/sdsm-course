VPN: приватный туннель поверх чужой сети

GRE заворачивает исходный пакет в новый заголовок и доставляет его через любую IP-сеть как единый транзитный поток. IPSec поверх GRE добавляет шифрование там, где транзитная сеть недоверенная.

01 — ТЕОРИЯ
Из чего состоит решение VPN

Шесть понятий — от простого GRE до DMVPN.

Проще говоря: VPN строит туннель поверх обычного интернета, чтобы два удалённых офиса вели себя как одна локальная сеть.

GRE
Generic Routing Encapsulation — простой протокол туннелирования: заворачивает любой пакет (включая не-IP) в новый IP-заголовок для транзита через промежуточную сеть.
GRE без шифрования
Сам по себе GRE не шифрует и не проверяет целостность — это просто инкапсуляция. Транзитная сеть видит содержимое, если не добавить IPSec поверх.
IPSec
Набор протоколов для шифрования (ESP) и/или проверки целостности (AH) IP-трафика между двумя точками. В связке с GRE чаще всего используется ESP.
GRE over IPSec
GRE даёт гибкость (multicast, любой протокол внутри, легко роутится динамическая маршрутизация внутри туннеля), IPSec — шифрование поверх этого туннеля.
IKE / Phase 1 и 2
Phase 1 устанавливает защищённый канал управления между пирами, Phase 2 согласовывает параметры для шифрования самого трафика (SA).
DMVPN
Dynamic Multipoint VPN — технология для построения множества туннелей hub-and-spoke (и spoke-to-spoke) без ручной настройки каждого туннеля отдельно.
— ЧАСТЫЕ ЗАБЛУЖДЕНИЯ
Что обычно путают

Типичные неверные представления про эту тему — и как на самом деле.

КажетсяVPN всегда означает шифрование трафика.
На делеVPN — это про логическую изоляцию и туннелирование; GRE, например, не шифрует данные — для конфиденциальности нужен IPSec поверх него.
КажетсяDMVPN — это просто много туннелей точка-точка.
На делеDMVPN использует multipoint GRE с NHRP, что позволяет строить прямые (spoke-to-spoke) туннели по требованию, без ручной full-mesh конфигурации.
02 — ПРОЦЕСС
Что происходит с пакетом по дороге

Четыре шага от исходного пакета до доставки на удалённой площадке.

  • 1GRE-инкапсуляция — исходный пакет получает новый заголовок с адресами туннельных интерфейсов.
  • 2IPSec (если настроен) — GRE-пакет целиком шифруется и/или подписывается (ESP/AH).
  • 3Транзит — пакет идёт через обычную IP-сеть, которая видит только внешний заголовок.
  • 4Декапсуляция — на удалённой площадке пакет расшифровывается и деинкапсулируется из GRE.
— ПРИМЕР
CLI-пример

Готовый конфиг для копирования — синтаксис Cisco IOS, адаптируйте под свою схему адресации.

GRE-туннель между площадками 
Router(config)# interface Tunnel0
Router(config-if)# ip address 172.16.0.1 255.255.255.252
Router(config-if)# tunnel source GigabitEthernet0/0
Router(config-if)# tunnel destination 203.0.113.10
Router(config-if)# tunnel mode gre ip
Router# show interfaces tunnel 0

Это только GRE — без IPSec поверх трафик внутри туннеля идёт в открытом виде.

03 — ГЛОССАРИЙ
Термины модуля

Короткий справочник — можно оставить открытым рядом с CLI.

ESP
Encapsulating Security Payload — протокол IPSec, шифрующий и опционально подписывающий данные.
AH
Authentication Header — протокол IPSec для проверки целостности и подлинности без шифрования содержимого.
SA
Security Association — согласованный набор параметров шифрования между двумя точками IPSec-туннеля.
Tunnel / Transport mode
Tunnel заворачивает весь исходный IP-пакет в новый; transport шифрует только payload, оставляя оригинальный IP-заголовок.
Keepalive туннеля
Периодические пакеты, проверяющие, что удалённый конец GRE-туннеля жив.
Split tunneling
Режим, при котором через VPN идёт только часть трафика, остальное — напрямую в интернет.
Hub-and-spoke
Топология VPN, где все точки (spoke) подключены к центральному узлу (hub), а не друг к другу напрямую.
MTU в туннеле
Добавление GRE/IPSec-заголовков уменьшает полезный MTU — может вызывать фрагментацию, если не учтено.
