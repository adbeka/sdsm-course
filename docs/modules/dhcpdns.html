DHCP и DNS: автоматическая выдача адресов и разрешение имён

Хост не рождается с IP-адресом и не умеет резолвить имена сам — DHCP выдаёт адрес и параметры сети, DNS переводит имена в адреса. Без них работает только то, что настроено вручную.

DORA через DHCP relay
ключевой узел на схемесоседний / промежуточный узел
  1. 1PC1: DHCPDISCOVER — broadcast, ищет DHCP-сервер в своей подсети
  2. 2R1 (ip helper-address): юникастом пересылает запрос на 10.10.10.53
  3. 3Сервер: DHCPOFFER — предлагает 10.10.20.50/24, шлюз, DNS
  4. 4PC1: DHCPACK получен — адрес закреплён, известен DNS-сервер

Без ip helper-address на роутере DHCPDISCOVER (broadcast) не выйдет за пределы своей подсети — клиент в VLAN 20 никогда не достучится до сервера в другой сети сам по себе.

01 — ТЕОРИЯ
Из чего складывается DHCP и DNS

Шесть понятий: от DORA до того, почему резолвер не идёт сразу к нужному серверу.

Проще говоря: DHCP выдаёт хосту адрес и параметры сети при включении, DNS потом переводит понятные людям имена в IP-адреса, которыми оперирует сеть.

DORA
Discover → Offer → Request → Ack — четыре шага, которыми клиент получает адрес: не «спрашивает и сразу получает», а именно предлагает/подтверждает, чтобы не было конфликтов при нескольких DHCP-серверах.
DHCP relay (ip helper-address)
DHCPDISCOVER — широковещательный кадр, а роутеры broadcast между подсетями не пропускают. ip helper-address на интерфейсе-шлюзе превращает его в юникаст до реального сервера.
Lease (аренда адреса)
Адрес выдаётся не навсегда, а на срок аренды. Ближе к его истечению клиент пытается продлить тот же адрес, не запуская DORA заново.
Рекурсивный резолвер
Хост обычно спрашивает не напрямую у authoritative-сервера домена, а у рекурсивного резолвера (например, у провайдера или corporate DNS), который сам обходит корневые/TLD/authoritative серверы.
Типы записей DNS
A/AAAA — имя в IPv4/IPv6, PTR — обратная запись (IP в имя), CNAME — псевдоним на другое имя, MX — сервер почты для домена.
DHCP options
Кроме самого адреса DHCP передаёт параметры: option 3 (шлюз), option 6 (DNS-серверы), option 66/67 (PXE-загрузка) — всё, что нужно хосту, чтобы полноценно работать в сети.

Что обычно путают

Типичные неверные представления про эту тему — и как на самом деле.

КажетсяDHCP-запросы всегда доходят до сервера в другой подсети сами по себе.
На делеDHCPDISCOVER — это broadcast, который роутер по умолчанию не пропускает между подсетями; нужен ip helper-address (DHCP relay).
КажетсяDNS-запрос всегда идёт напрямую к authoritative-серверу нужного домена.
На делеОбычно сначала опрашивается рекурсивный резолвер, который сам обходит корневые/TLD/authoritative серверы, если ответа нет в кэше.
02 — ПРОЦЕСС
Как хост получает адрес и находит нужный сервер

От включения хоста до первого успешного DNS-запроса.

  • 1DHCPDISCOVER — клиент рассылает broadcast-запрос в поисках DHCP-сервера.
  • 2Relay при необходимости — если сервер в другой подсети, роутер с ip helper-address пересылает запрос юникастом.
  • 3DHCPOFFER → DHCPREQUEST → DHCPACK — сервер предлагает адрес, клиент подтверждает, адрес закрепляется.
  • 4Клиент получает DNS-сервер в составе DHCP-ответа (option 6).
  • 5DNS-запрос к резолверу — приложение обращается по имени, резолвер возвращает IP-адрес.
— ПРИМЕР
CLI-пример

Готовый конфиг для копирования — синтаксис Cisco IOS, адаптируйте под свою схему адресации.

DHCP relay и DHCP-пул на роутере 
Router(config)# interface GigabitEthernet0/1
Router(config-if)# ip helper-address 10.10.10.53
Router(config-if)# exit
Router(config)# ip dhcp excluded-address 10.10.20.1 10.10.20.10
Router(config)# ip dhcp pool USERS
Router(dhcp-config)# network 10.10.20.0 255.255.255.0
Router(dhcp-config)# default-router 10.10.20.1
Router(dhcp-config)# dns-server 10.10.10.53
Router(dhcp-config)# lease 7
Router# show ip dhcp binding

ip dhcp excluded-address обязателен — иначе DHCP-пул может выдать адрес, который уже занят шлюзом или статическими устройствами.

— ПРАКТИКА
Лабораторная работа

Попробуйте сами в Packet Tracer/GNS3 или на реальном стенде, прежде чем открывать решение.

В офисе один центральный DHCP/DNS-сервер на 10.10.10.53. Клиентский VLAN 20 (10.10.20.0/24) находится на другом роутере — сейчас клиенты в нём не получают адреса.

  1. Настройте ip helper-address на интерфейсе VLAN 20 в сторону 10.10.10.53
  2. На сервере (или локальном пуле) исключите первые 10 адресов подсети под статику
  3. Убедитесь, что клиент получает адрес именно из 10.10.20.0/24, а не из чужого пула
  4. Проверьте, что клиенту приходит правильный DNS-сервер (не шлюз по ошибке)
  5. Посмотрите активные аренды через show ip dhcp binding
Показать решение
Решение 
Router(config)# interface Vlan20
Router(config-if)# ip address 10.10.20.1 255.255.255.0
Router(config-if)# ip helper-address 10.10.10.53
Router(config-if)# exit
Router# show ip dhcp binding
Router# show run interface Vlan20

Как проверить: На клиенте: ipconfig /all (Windows) или show ip interface brief (Cisco) — должен появиться адрес из 10.10.20.0/24 и корректный DNS-сервер 10.10.10.53.

03 — ГЛОССАРИЙ
Термины модуля

Короткий справочник — можно оставить открытым рядом с CLI.

DORA
Discover, Offer, Request, Ack — четыре сообщения процесса получения адреса по DHCP.
ip helper-address
Команда на интерфейсе роутера, превращающая широковещательный DHCP-запрос в юникаст до конкретного сервера.
Lease time
Срок, на который клиенту выдан адрес, после которого его нужно продлевать или заново запрашивать.
Рекурсивный резолвер
DNS-сервер, который берёт на себя весь поиск ответа по цепочке других серверов, а клиенту отдаёт уже готовый результат.
Authoritative-сервер
DNS-сервер, который хранит оригинальные записи конкретного домена и отвечает на вопросы о нём с полным доверием.
PTR-запись
Обратная DNS-запись: перевод IP-адреса в доменное имя, используется, например, почтовыми серверами для проверки репутации отправителя.
TTL (DNS)
Время, на которое ответ DNS-запроса можно закэшировать, не спрашивая сервер заново.
